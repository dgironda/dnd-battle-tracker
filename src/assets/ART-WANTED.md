# Art wanted — hand-drawn replacements

Every visible CSS border in the app has been removed: the look now comes from
Emily's SVGs, and anything still drawn by the browser is a placeholder. This
file lists what lost its border and therefore has no edge at all right now, so
it can be drawn properly.

**64 border declarations were removed.** Two things still carry a CSS border and
should stay that way — they are invisible scaffolding that `border-image` needs
in order to paint an SVG at all:

- the battle tracker's row plaques (`src/fixes.css`)
- the manager panels' container art (`src/managers.css`)

## What the existing hand-drawn art looks like

The pieces already drawn this way are a useful reference for style:

| what | file |
| --- | --- |
| Row plaques | `table_item-*.svg`, `table_header-*.svg` |
| Manager frames | `container_hero-manager.svg`, `container_monster-manager.svg` |
| Checkbox + tick | `checkbox_hand-*.svg`, `check_hand-*.svg` |
| Name underline | `underline_pencil-*.svg` |
| Scroll roll | `container_scroll-roll.svg` |
| Hiding eye | `icon_eye-open.svg`, `icon_eye-shut.svg` |

The last two are generated by `tools/generate-hand-art.mjs` rather than drawn —
they are stand-ins and would be better hand-drawn. Anything Emily draws can just
replace the file at the same name.

## Wanted

A frame or edge for each of these. Several variants of each would be ideal: the
tracker picks between variants at random per row/cell so nothing looks stamped.


### The "Hiding" eye — Monster Manager

The Monster Manager's Hiding column is an eye rather than a checkbox: **open**
when the monster is in plain sight, **shut** when it is hidden from the party.
Clicking it toggles between the two.

`icon_eye-open.svg` and `icon_eye-shut.svg` are generated stand-ins in the same
hand as the checkboxes. Two constraints if they get redrawn:

- **130 x 130 viewBox**, matching the other icons, with the drawing roughly
  centred and filling most of it.
- Drawn in **black** on transparent. The page recolours and fades it (75%
  opacity when open, full when shut), so a coloured file would fight that.

The shut state is the one that matters at a glance down the roster — it should
read as clearly different in silhouette, not just a variation of the open eye.

### The scroll's roll — **the one real gap**

`container_scroll-side.svg` has no rod in it. Down its left edge there are two
small knobs at the corners and plain parchment between them, which is fine at
full size but reads as two blobs floating in the paper when the side-car panel
is only ~300px tall. The panel now slides that roll out first and then unrolls
the sheet, so the roll has to look like something wound up.

`container_scroll-roll.svg` is a generated stand-in: a tube of wound parchment
with a turned knob on each end, in the scroll's own palette. A drawn one would
be much better. Two constraints if it gets redrawn:

- **120 x 600 viewBox**, with everything shaped inside the top 110 and bottom
  110 units. It is nine-sliced vertically (`18.3333% 0 fill`), so the 380 units
  between the caps must be nothing but vertical bands — anything with a shape
  in it will smear when the panel is tall.
- Palette in use: parchment `#ceb59c` / `#d2bba4` / `#bd9d7d`, ink `#3e1709`,
  wood `#79412e` / `#4f2314` / `#a06a4c`.

The section rules inside the panel are `underline_pencil-{1,2,3}.svg`, reused
as statblock dividers. Purpose-drawn rules would be welcome but are not urgent.

## Also worth knowing

- These CSS variables are now unused and can go once the art lands:
  `--color-photo-border`, `--color-photo-border-hover`,
  `--color-photo-preview-border`, `--color-photo-close-border`.
- The overall goal is that the whole thing reads as if a DM sketched it in
  pencil, so wobble, uneven line weight and the odd gap are all wanted, not
  faults to clean up.
